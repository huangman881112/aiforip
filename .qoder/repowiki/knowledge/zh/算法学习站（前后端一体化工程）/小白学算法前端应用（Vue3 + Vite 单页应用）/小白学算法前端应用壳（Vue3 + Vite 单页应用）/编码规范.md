- API 客户端统一采用「后端优先 + 失败降级」模式：每个接口先尝试 `checkBackend()` 命中后端，失败则回落到 `localStorage` 或 `data/*.js` 中的静态数据，确保无后端时功能完整。
- 算法元数据集中在 `data/algorithms.js` 作为单一数据源，所有列表、详情页复杂度块、导航分类均从该文件派生，新增算法只需在此处追加条目。
- 路由与可视化组件解耦：路由仅声明 category 级页面（如 `/algorithms/sorting`），具体算法详情通过 `components/algorithms/vizRegistry.js` 按 algorithm id 懒加载对应 `*Detail.vue`。
- 页面路由使用 `meta.requiresAuth` / `meta.public` 标记权限，在 `router.beforeEach` 中统一拦截并跳转登录页携带 `redirect` query。
- Pinia store 通过 `defineStore` 暴露 `state/getters/actions`，跨模块共享用户登录态（`useUserStore`），并在路由守卫和 App 挂载时调用 `init()` 恢复会话。
- 算法可视化逻辑抽取为 `composables/useXxxVisualization.js`，各 Detail 组件通过组合式函数复用排序/搜索/图遍历的动画步骤生成逻辑。
